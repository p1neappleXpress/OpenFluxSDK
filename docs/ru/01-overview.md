# Обзор

*[Read in English](../01-overview.md)*

## Зачем это существует

OpenFlux — это TCP-туннель с подключаемыми транспортами: каждый транспорт
переносит трафик туннеля через свой реальный протокол (синхронизация
курсора в совместном редакторе документов, приложение для доски, канал
сигнализации голосового звонка, ...), поэтому туннель не привязан к одному
конкретному формату на проводе. Раньше каждый транспорт был Go-кодом,
скомпилированным в ядро. Добавление нового означало пересборку ядра, а на
Android — новый APK.

В этом вся мотивация: **поставлять новые транспорты как данные, а не как
пересборку.** Транспорт теперь — это подписанный `.js`-файл (или подписанный
пакет `.flux` — см. [04-signing-and-packaging.md](04-signing-and-packaging.md)),
который просто кладётся в директорию, которую exit/узел читает при старте.
Никаких изменений в ядре, никакого обновления приложения.

## Составные части

```
                     ┌─────────────────────────────────┐
                     │         your transport.js         │
                     │  (auth, framing, reconnect logic) │
                     └───────────────┬───────────────────┘
                                     │ runs inside
                     ┌───────────────▼───────────────────┐
                     │      one goja Runtime per          │
                     │      transport instance            │
                     │  (pure Go interpreter, no cgo)     │
                     └───────────────┬───────────────────┘
                                     │ calls into
                     ┌───────────────▼───────────────────┐
                     │         host API (Go)              │
                     │  http / ws / udp / webrtc / cookies │
                     │  / codecs / crypto / concurrency    │
                     └───────────────┬───────────────────┘
                                     │ real I/O
                              the actual network
```

- **Один Runtime goja на экземпляр транспорта.** goja — однопоточный и не
  безопасен для использования из нескольких горутин одновременно. Весь
  реальный I/O (HTTP, WebSocket, UDP, WebRTC) выполняется в Go-горутинах;
  результаты маршалятся обратно в собственный event loop транспорта, прежде
  чем их увидит ваш JS. Вам никогда не нужно об этом думать — именно поэтому
  каждый асинхронный вызов host API возвращает Promise, а не блокирует.
- **Host API намеренно не ограничен.** Никакого allowlist хостов, никаких
  флагов возможностей, никакого «этот транспорт не может открывать raw
  сокеты». Подключайтесь куда угодно, запрашивайте что угодно, открывайте
  настоящий WebRTC PeerConnection, если нужно. Свобода — это и есть суть:
  автору транспорта нужна полная гибкость, чтобы достоверно реализовать
  реальный протокол, включая всё, что этот протокол на самом деле делает
  «под капотом».
- **Подпись — это вся граница безопасности.** Каждый `.js`-файл (или пакет
  `.flux`) проверяется против публичного ключа ed25519, которому доверяет
  exit/узел, *до того*, как выполнится хоть одна строка кода. Не существует
  частично доверенного пути, никакого «запустить, но ограничить, что он
  может делать» — либо подписано и запускается, либо не подписано и
  отклоняется целиком. См.
  [04-signing-and-packaging.md](04-signing-and-packaging.md).

## Контракт, который реализует ваш скрипт

Транспорт — это один глобальный объект:

```js
var Transport = {
  info()               { /* manifest: name, version, params it needs, ... */ },
  open(cfg)            { /* connect. cfg = {url, params: {...}} */ },
  write(bytes)         { /* send one packet. bytes = ArrayBuffer */ },
  close()              { /* torn down */ },
  onEvent(kind, payload) { /* optional: OOB messages from the host app */ },
};
```

Пять функций. `info()` выполняется один раз, синхронно, сразу после
загрузки файла. `open()` выполняет вашу авторизацию/подключение и вызывает
`setState(...)` по мере изменения состояния соединения — это *единственный*
способ, которым Go-сторона узнаёт, подключены вы или нет. `write()`
вызывается один раз на каждый исходящий пакет. `close()` выполняется при
остановке. `onEvent()` опционален — для вещей вида «вот куки от капчи,
которую вы попросили решить приложение вне канала».

Полный, точный контракт — каждое поле, каждая гарантия по времени — находится
в [templates/template.js](../../templates/template.js), который
поддерживается побайтово синхронным с `transport/script/js/template.js` в
основном репозитории. Прочитайте его от начала до конца перед написанием
первого транспорта; он короткий и является настоящим референсом, а не
пересказом.

## Что уже выпущено как скриптовый транспорт

На момент `feature/scripted-transports` семь транспортов работают именно
так — точный статус проверки каждого смотрите в `CHANGELOG.md` основного
репозитория на этой ветке. Если вы делаете что-то похожее (инструмент
совместной работы с документами, протокол чата/relay на WebSocket, что-то
с браузероподобным флоу авторизации), чтение одного из существующих портов
часто быстрее, чем начинать с шаблона — `mailru.js` самый короткий и простой
пример от начала до конца; `cupsonline.js` показывает изоляцию нескольких
сессий (`http.newSession()`); `vyandex.js` показывает ограниченный по
количеству параллелизм (`concurrency.pool`); `oneme-webrtc.js` показывает
примитив WebRTC в реальном использовании.
