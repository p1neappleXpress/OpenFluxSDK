# Настройки и страницы настройки

*[Read in English](../07-settings-and-setup-pages.md)*

Транспорту обычно нужно от пользователя больше, чем одна ссылка: токен, регион,
число повторов, а иногда вход, который можно сделать только на настоящей
странице. В OpenFlux для этого два инструмента, и оба заканчиваются страницей во
встроенном браузере приложения:

|  | **Настройки** | **Страница настройки** |
|---|---|---|
| Что это | Вы *объявляете*, что можно менять, в `info().params` | Вы *просите* страницу во время работы через `raise()` |
| Кто строит страницу | OpenFlux (мастер, собранный из вашего объявления) | Вы (свой HTML, настоящий сайт или свой маленький сервер) |
| Когда появляется | Пользователь нажимает **Настройки** у транспорта | Когда решаете вы: нужен вход, капча, привязка |
| Как значения доходят до вас | `cfg.params` в `open(cfg)` при каждом запуске | `onEvent("cookiesApplied")`, затем `cookieJar.get()` |
| Писать HTML | не нужно | нужно (для настоящего сайта нет) |

Большинству транспортов нужны только **настройки**. **Страница настройки** нужна,
когда транспорт не может работать, пока в браузере что-то не произойдёт.

Всё ниже проверено на настоящем ядре и настоящем браузере приложения. В конце
показано, как попробовать всё это у себя, без приложения.

---

## 1. Настройки за пять минут

Объявите их в `info()`. Кода больше нет:

```js
info: function () {
  return {
    name: "my-transport",
    version: "1.0.0",
    params: [
      { key: "url",   label: "Ссылка на документ", type: "url", required: true },       // поле профиля
      { key: "token", label: "API-токен", type: "secret", required: true },             // настройка
      { key: "retries", label: "Число повторов", type: "number", default: 3, min: 1, max: 10 },
      { key: "compress", label: "Сжимать", type: "boolean", default: false },
    ],
  };
},

open: async function (cfg) {
  var url = cfg.url;                        // что пользователь ввёл в профиле
  var token = cfg.params.token;             // настройка, всегда строка
  var retries = Number(cfg.params.retries); // "3", пока пользователь не изменит
  var compress = cfg.params.compress === "true";
  ...
}
```

Установите скрипт в приложение. На вкладке **Транспорты** у карточки вашего
транспорта появится кнопка **Настройки**. Она открывает форму, собранную из
вашего объявления: с проверкой, кнопкой «По умолчанию» и «Сохранить». Такая же
кнопка есть в редакторе профиля, если профиль использует ваш транспорт.
Значения сохраняются вместе со скриптом, и при следующем запуске соединения вы
получаете их в `cfg.params`.

Увидеть мастер, не трогая приложение:

```bash
scripttest -script my-transport.js -pubkey "$(cat dev.pub)" -settings -open
```

## 2. Как объявлять настройки

### Поле профиля и настройки

У профиля одно поле значения рядом с выбором транспорта. Это ваш **первый**
параметр, его значение приходит как `cfg.url` **и** как `cfg.params[key]` под
собственным ключом — мастер спрашивает его тоже, рядом с остальными, подставив
то, что сейчас лежит в поле профиля. Меняйте его хоть в поле профиля, хоть в
мастере — это одно и то же значение; приложение может показать только быстрое
поле, только мастер, или оба. Все остальные параметры — **настройки**: их
спрашивает только мастер.

Если у транспорта вообще нет входа на уровне профиля (всё — настройки), скажите
это через `scope`:

```js
params: [
  { key: "token", label: "Токен", type: "secret", required: true, scope: "settings" },
]
```

`scope` — `"profile"` или `"settings"`. Поставьте `"profile"` у более позднего
параметра, чтобы полем профиля стал он, а не первый. Полем профиля может быть
один параметр; второй `"profile"` станет настройкой. У транспорта с одним
единственным параметром (тем самым, полем профиля) теперь тоже есть мастер —
просто с этим одним полем, так что он не обречён быть только-быстрым-полем.

Читайте его как удобно — оба способа всегда совпадают:

```js
open: function (cfg) {
  var token = cfg.params.token;   // настройка, по ключу
  var board = cfg.url;            // поле профиля, по-старому
  var sameBoard = cfg.params.url; // поле профиля, по ключу — тоже работает
}
```

### Поля параметра

| поле | смысл |
|---|---|
| `key` | Имя, по которому вы читаете значение. Обязательно, уникально. |
| `label` | Что видит пользователь. По умолчанию — ключ. |
| `type` | `text` (по умолчанию), `url`, `secret`, `number`, `boolean`, `select`, `textarea`. Неизвестный тип показывается как `text`. |
| `required` | Мастер не сохранит, пока поле пусто (для boolean не применяется). |
| `default` | Что лежит в `cfg.params`, пока пользователь ничего не задал. Строка, число или boolean. |
| `description` | Пояснение под полем. |
| `placeholder` | Серая подсказка внутри поля. |
| `options` | Варианты для select: `["a", "b"]` или `[{ value: "eu", label: "Европа" }]`. |
| `min`, `max` | Границы для `number`. |
| `pattern` | Регулярное выражение, которому должно соответствовать значение `text`/`url`. Держитесь общего подмножества: страница проверяет его как JavaScript `RegExp`, ядро — как RE2. |
| `group` | Заголовок раздела. Параметры с одинаковым `group` подряд стоят под одним заголовком. |
| `advanced` | Спрятать в «Дополнительно». |
| `scope` | `"profile"` или `"settings"`, см. выше. |

Как выглядит каждый тип и что он проверяет:

| тип | поле | проверка |
|---|---|---|
| `text` | однострочное поле | `pattern` |
| `url` | однострочное поле | должно содержать `://`, `pattern` |
| `secret` | поле пароля с кнопкой «показать» | не обрезается: пробелы могут быть частью секрета |
| `number` | поле, принимающее `3`, `2.5`, `2,5` | число, `min`, `max` |
| `boolean` | переключатель | нет |
| `select` | выпадающий список | одно из `options` |
| `textarea` | многострочное поле | `pattern`; не обрезается |

### Что получает ваш скрипт

- **Только строки.** Число — это `"7"`, boolean — `"true"` или `"false"`.
  Приводите типы в `open()`. Текст обрезается по краям (кроме `secret` и
  `textarea`).
- **Значения по умолчанию подставлены.** Настройка с `default` есть в
  `cfg.params`, даже если пользователь ни разу не открывал мастер: `|| "3"` в
  коде не нужен.
- **Пусто — это `""`.** Не заданная настройка без `default` — пустая строка.
- **Ключи, занятые ядром.** В `cfg.params` также лежат `path`, `pubkey`, `name`
  и `exit` (boolean: это выходной процесс?). Настройка с таким именем
  игнорируется, она не может их подменить. Не объявляйте параметры с такими
  ключами.
- **Изменения вступают в силу при следующем подключении.** Значения читаются при
  запуске транспорта. Мастер говорит об этом пользователю.

Сохраняется каждый объявленный ключ; страница не может добавить другие. (Своя
страница, ниже, которая не объявляет параметров вообще, может присылать любые
ключи.)

### Проверьте своё объявление

Ошибки в объявлении не мешают скрипту загрузиться: приложения подставляют
обычное текстовое поле. Но их легко исправить, когда видишь:

```bash
scripttest -script my-transport.js -pubkey "$(cat dev.pub)" -settings -duration 1s
# WARN  param "retries": min is greater than max
# WARN  param "mode": a select needs options
```

Тот же список лежит в `paramProblems` отчёта `--inspect-script` ядра. Он ловит
отсутствующий и повторяющийся ключ, неизвестный тип, select без options,
`min > max`, паттерн, который не компилируется, значение по умолчанию, которое
отвергают собственные правила, и неверный `scope`.

## 3. Мастер настроек

Мастер — одна самодостаточная страница: светлая и тёмная темы, проверка по ходу
ввода, красное сообщение под неверным полем, **По умолчанию** (вернуть ваши
значения по умолчанию) и **Сохранить**. Обязательные поля помечены `*`;
`advanced` лежат под **Дополнительно**, которое раскрывается само, если поле
внутри неверно.

HTML для него писать не нужно. Если нужна своя страница, определите
`Transport.settings(values)`:

```js
Transport.settings = function (values) {
  // values: текущие настройки строками, с вашими значениями по умолчанию.
  return '<!doctype html><title>Моя страница</title><form>…</form>' +
         '<script>document.querySelector("form").onsubmit = function (e) {' +
         '  e.preventDefault(); openfluxSubmit({ token: document.querySelector("input").value });' +
         '};<\/script>';
}
```

Правила для `settings()`:

- Возвращает строку HTML или `{ html: "…" }`. Больше ничего не принимается.
- Выполняется **до того, как о скрипте что-либо решено или он подключён**, поэтому
  работает так же, как `info()`: без сети, без сокетов, без куки, три секунды,
  синхронно. Вызов `http.fetch` и всего, что выходит наружу, бросает ошибку.
  Сама страница, конечно, может обращаться наружу из браузера.
- Страница не больше 512 КиБ.
- Значения страница возвращает через `window.openfluxSubmit({...})` (раздел 5).
  Что она пришлёт, то и сохранится как ваши настройки. Если вы объявили
  параметры, останутся только объявленные ключи.
- Диалог мастера закрывается, когда страница отправила данные. Проверяйте ввод
  в самой странице до вызова `openfluxSubmit`.

У скрипта со своей страницей есть кнопка **Настройки**, даже если он не
объявляет параметров.

## 4. Страницы настройки во время работы

Когда транспорт не может продолжать, пока пользователь что-то не сделает,
попросите приложение показать страницу:

```js
raise("needsSetup",      { html: PAGE,                           reason: "Привяжите аккаунт" });
raise("needsSetup",      { url: "https://service.example/login", reason: "Войдите" });
raise("captchaRequired", { url: "http://127.0.0.1:41234/",       reason: "Привяжите аккаунт" });
```

`needsSetup` и `captchaRequired` работают совершенно одинаково; берите то имя,
которое лучше читается. Поднимать можно из `open()` («ничего ещё не
настроено») или позже. Передавайте **либо** `html`, **либо** `url`, не оба.

### Три вида страниц

1. **Настоящий сайт** (`url`, https). Пользователь входит или проходит проверку
   во встроенном браузере. Приложение собирает куки сайта и отдаёт их вам.
2. **Встроенная страница** (`html`). Вы её собираете, приложение рисует. Сетевого
   запроса за ней нет. У её `fetch()` нет настоящего origin; для таких случаев:
3. **Свой сервер** (`url` на `http://127.0.0.1:<порт>`). Вы запускаете его через
   `httpserver.listen()`, приложение открывает. Настоящий origin, свои маршруты,
   OAuth-редирект на `http://127.0.0.1:<порт>/callback` — что нужно.

```js
var server = httpserver.listen(function (req) {
  if (req.path === "/") return { headers: { "Content-Type": "text/html; charset=utf-8" }, body: PAGE };
  if (req.path === "/api/check") return checkToken(req.query.token);   // может быть async
  return { status: 404, body: "not found" };
});
raise("needsSetup", { url: "http://" + server.addr + "/", reason: "Привяжите аккаунт" });
```

`examples/setup-own-server.js` — готовый полный пример.

### Что пропускает ядро

`raise()` этих двух видов проверяет свой payload **в ядре**, до того как его
увидит какое-либо приложение, и бросает `TypeError` в ваш скрипт, если он
неверный. Об ошибке вы узнаёте при написании, а не в работе.

| что вы поднимаете | результат |
|---|---|
| `url: "https://…"` | разрешено |
| `html: "…"` (до 512 КиБ) | разрешено |
| `url: "http://127.0.0.1:<порт>/…"`, где `<порт>` — сервер, который **вы** запустили через `httpserver.listen()` и не закрыли | разрешено (также `localhost`, `[::1]`) |
| `http://` куда-либо ещё, чужой loopback-порт, `http://127.0.0.1/` без порта | `TypeError` |
| `file:`, `javascript:`, `data:`, любая другая схема | `TypeError` |
| `html` и `url` вместе | `TypeError` |
| страница больше 512 КиБ | `TypeError` (отдавайте её через `httpserver.listen()`) |

`reason` обрезается до 200 символов. Для **своей страницы** (html или свой
сервер) приложение показывает его как **заголовок диалога**: пишите короткую
человеческую фразу («Привяжите аккаунт»). Для проверки настоящего сайта это
код (`"login"`, `"smartcaptcha"`), формулировку к которому приложение подбирает
само.

На **выходной ноде** клиенту можно показать только встроенный `html`. Адрес
`http://` на loopback выхода ничего не значит на машине клиента, поэтому ядро
клиента его отбрасывает.

### Получение ответа

Что бы пользователь ни отправил, оно приходит в ваш обработчик тем же путём,
каким всегда шли куки решённой капчи:

```js
onEvent: function (kind, payload) {
  if (kind === "cookiesApplied") {
    var values = cookieJar.get();          // {token: "…", …}: что отправила страница
    ...
  }
}
```

`cookieDomain` в `info()` (любой URL `https://…/`) определяет, где значения
лежат в вашем jar; без него берётся значение по умолчанию, а чтение через
`cookieJar.get()` работает в обоих случаях. Ядро также хранит их в своём
хранилище куки (обычный JSON-файл рядом с данными приложения, как куки решённой
капчи) и кладёт обратно в ваш jar **до запуска `open()`** при следующем старте,
чтобы пользователь не повторял настройку: проверяйте `cookieJar.get()` в начале
`open()` и пропускайте страницу, если нужное уже есть (см.
`examples/setup-own-server.js`). Всё это не зависит от того, настоящие ли это
куки или ваши собственные поля.

Пока страница открыта, транспорт считается ожидающим: ядро обходит его.
Пользователь также может закрыть диалог кнопкой **Позже**; если настройка вам
всё ещё нужна, поднимите её снова после разумной паузы (а не в плотном цикле).

## 5. `window.openfluxSubmit`

Любая страница настройки и мастер, которые показывает приложение, могут вызвать:

```js
window.openfluxSubmit({ token: "abc", port: 8080, remember: true });
```

- Payload — **плоский объект** или `{ client: {…}, node: {…} }` (сегодня
  доставляется только половина `client`; `node` пока никуда не идёт).
- Значения становятся **строками**: строка остаётся, число или `true`/`false`
  превращается в свой текст. `null`, объекты и массивы отбрасываются; если нужна
  структура, шлите `JSON.stringify(x)`.
- Должно остаться хотя бы одно значение, иначе приложение откажет.
- Функция ничего не возвращает. Не ждите её результата.
- Вызов **завершает** страницу: приложение доставляет значения и закрывает диалог.

### Когда функция существует

- На **встроенной странице** (`html`) функция есть **до запуска собственных
  скриптов страницы**. Можно пользоваться сразу.
- На странице **с вашего сервера** она добавляется, когда страница загрузилась.
  Вызывайте её из обработчиков событий (клик, отправка формы): это естественно.
  Если нужно вызвать при загрузке, проверьте `typeof window.openfluxSubmit ===
  "function"`, а иначе дождитесь события:

```js
window.addEventListener("openflux-ready", function () { /* openfluxSubmit уже есть */ });
```

- В обычном браузере (пока вы рисуете страницу) её нет. Защитите вызов, чтобы
  страница работала и там.

### Она остаётся с вашей страницей

Функция привязана к адресу вашей страницы. Если страница ведёт на другой сайт или
ваша страница ушла на другой origin, то, что пришлёт тот сайт, отбрасывается:
чужая страница не может передать данные вашему скрипту. Обычный сайт, открытый
как проверка (вид 1), функцию не получает вообще.

## 6. Попробуйте без приложения

`scripttest` играет роль приложения.

### Мастер настроек

```bash
scripttest -script my-transport.js -pubkey "$(cat dev.pub)" -settings -open
```

Он печатает адрес страницы (`-open` открывает её в вашем браузере), строки `WARN`
о проблемах объявления и, когда вы нажимаете «Сохранить», печатает ровно то, что
получил бы скрипт:

```
[21:24:03] SAVED, the script would get as cfg.params:
{
  "compress": "true",
  "retries": "5",
  "token": "s3cr#t;1"
}
```

Флаги: `-param "k=v,k2=v2"` подставляет значения, `-lang ru|en` выбирает слова,
которые добавляет страница, `-duration` — сколько ждать (останавливается на
первом корректном «Сохранить»).

### Страница настройки, пока транспорт работает

Запустите скрипт как обычно. Когда он поднимет страницу настройки, `scripttest`

- отдаёт вашу страницу на `127.0.0.1` с `window.openfluxSubmit` внутри
  (встроенной странице функция добавляется до её скриптов; страница с вашего
  сервера идёт через `scripttest`, который её добавляет, так что страница такая
  же, как в приложении),
- печатает адрес (`-open` показывает её в браузере),
- и доставляет то, что отправила страница, в ваш `onEvent("cookiesApplied")`.

```bash
scripttest -script setup-own-server.js -pubkey "$(cat dev.pub)" \
  -url "wss://ws.postman-echo.com/raw" -open -duration 120s
```

Для проверки настоящего сайта (вид 1) из командной строки куки собрать нельзя:
передайте их через `-cookies-file`.

### Без людей: `-submit`

```bash
scripttest -script setup-own-server.js -pubkey "$(cat dev.pub)" \
  -url "wss://ws.postman-echo.com/raw" -submit '{"token":"tok-1234"}' -duration 10s
```

`-submit` отвечает на первую страницу настройки так, будто её заполнил человек:
скрипт можно прогнать в CI, когда рядом никого нет.

### В приложении

Добавьте транспорт в профиль и откройте его **Настройки** прямо там (рядом с
быстрым полем, если оно есть — оба правят одно и то же значение). Для страницы
времени работы подключите этот профиль. Сохранённое принадлежит профилю/несущему,
а не установленному скрипту: два профиля с одним и тем же скриптом хранят свои
значения отдельно (обычный JSON-файл на устройстве, как хранилище куки: не
рассчитывайте, что он хранит секрет надёжно). Десктопное приложение передаёт их
ядру одной закодированной строкой, потому что значение в `.conf` обрывается на
`#` и `;`, которые в настройке могут быть; вы этого не видите.

---

## 7. Полезно знать

- **Старые скрипты продолжают работать.** Скрипт, объявляющий только `key`,
  `label`, `type` и `required`, читается как раньше: первый параметр — поле
  профиля, остальные — настройки. Приложение, в котором мастера ещё нет,
  игнорирует новые поля и показывает только первый параметр.
- **Настройки привязаны к устройству.** В ссылку `openflux://` они не входят;
  скриптовый транспорт ссылкой не передаётся.
- **Не кладите секреты в `default`.** Значение по умолчанию — открытый текст в
  вашем публичном скрипте.
- **Страница — это веб-страница.** Ваша страница и ваш сервер работают во
  встроенном браузере; доверия к ним столько же, сколько к скрипту (он подписан),
  но страница может обращаться к любому сайту, доступному браузеру. Не пишите
  токены в URL, которые логируете.
- **Сервер только на loopback.** У `httpserver.listen()` нет аргумента хоста:
  снаружи устройства до него не достучаться. Закройте его (`server.close()`),
  когда настройка закончена; при остановке транспорта он закроется сам.
- **На ноде мастер пока недоступен.** Настройки относятся к скрипту, который
  работает на клиенте. Установка скрипта на выходную ноду по SSH не сделана.

Раздел 5.

### `scripttest`

| флаг | смысл |
|---|---|
| `-settings` | открыть мастер настроек вместо запуска скрипта |
| `-open` | показать поднятые страницы настройки (и мастер) в вашем браузере |

| `-lang ru\|en` | слова, которые добавляет сгенерированный мастер |
| `-cookies-file` | куки для проверки настоящего сайта |
